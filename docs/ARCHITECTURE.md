# Архитектура

```
data/raw/dataset.csv
        │
        ▼
 clean() ─► split train/val/test ─► add_features() ─► Pipeline(prep + HistGradientBoosting)
        │                                                   │ квантили 0.1 / 0.5 / 0.9
        ▼                                                   ▼
   reports/eda                                 models/model.joblib, schema.json, metrics.json
                                                            │              │
                                                MLflow (метрики,           ▼
                                                параметры, артефакты)   export_onnx ─► model.onnx
                                                            │
                                                            ▼
                         FastAPI (/predict, /predict/batch, /health, /metrics, /model/info)
                                                            │
                                            Docker ─► GitHub Actions ─► сервер
```

## Решения и почему

| Решение | Почему |
|---|---|
| Градиентный бустинг (HistGradientBoosting) | Хорош на табличных данных, нативно переживает NaN, быстро учится, поддерживает квантильную loss |
| Три квантильные модели вместо одной | Продукту нужна вилка, а не точка; покрытие интервала — прямая метрика качества |
| Один `add_features()` для обучения и API | Исключает training-serving skew |
| `params.yaml` + DVC | Эксперимент = изменение параметров; воспроизводится одной командой |
| MLflow (sqlite) | Сравнение запусков без поднятия отдельного сервера |
| ONNX | Ускорение инференса и независимость от версии sklearn |
| Модель «запекается» в Docker-образ | Образ неизменяем: версия кода и модели всегда согласованы |
| Логи JSON с `request_id` | Любой странный ответ можно найти по id и воспроизвести по залогированному входу |

## Известные ограничения

- `/metrics` — in-process окно из последних 2000 запросов; для продакшена заменить на Prometheus.
- Дрейф данных не мониторится (следующий шаг: сравнение распределений входов с train, например Evidently).
- Квантильные модели обучаются независимо и могут пересекаться — в `model_service.py` вилка принудительно содержит медиану.
