# API-контракт MoverMate

> Договорённость между бэкендом и фронтендом, до кода. Единственный источник правды после реализации — Swagger (`/api/docs`) и `frontend/src/api/types.ts`; при расхождении исправляем сразу.
> Все пути с префиксом `/api`. JSON, UTF-8, даты — ISO 8601 (`2026-11-01`, время — UTC `…Z`).

## Компактный QR

- `QrMode = 'universal' | 'compact'`, по умолчанию `universal` (ссылка `{origin}/projects/{pid}/boxes/{n}`, открывается любой камерой). Менять режим проекта может только владелец (`403` участнику).
- Компактная строка: `MM1:` + 16 символов Base32 (`A–Z`, `2–7`), всего 20 ASCII-символов. Читает её встроенный сканер сайта.
- `POST /api/boxes/resolve-code` `{"code":"MM1:…"}` → `200 {"project_id","box_number"}`, только участнику проекта; `401` без входа; `404` для чужого, неизвестного или удалённого кода; `422` для неверного формата. Только чтение.
- `LabelOut.qr_payload`: в компактном режиме — строка `MM1:…`, в универсальном — `null` (ссылку собирает браузер из `qr_path`).
- Коды хранит `box_qr_codes` (миграция `0004_compact_qr`); код удалённой коробки остаётся занятым и никогда не выдаётся снова. Сканер принимает оба формата всегда, поэтому переключение режима не ломает старые наклейки. `VITE_COMPACT_QR_ENABLED=false` при сборке скрывает компактный режим.

## Общие соглашения

### Персональный план при создании проекта

`POST /api/projects/plan-preview` (нужна cookie-сессия) принимает
`{ "description": "Переезжаем с ребёнком и кошкой", "move_date": "2026-11-01", "consent": true }`.
Требуется явное согласие; описание 10–4000 символов после удаления пробелов по краям.
На AI-сервис отправляются только описание и дата. Проект, задачи, адреса и инвентарь из БД не читаются.
Возвращает редактируемый черновик:

```json
{
  "tasks": [{"title": "Подготовить переноску", "stage": "before", "offset_days": -3}],
  "first_day": ["Корм для кошки"]
}
```

Здесь 1–30 задач, до 20 предметов, названия 1–200 символов. `offset_days` — целое от -365 до 365:
`before` ≤ 0, `moving_day` = 0, `after` ≥ 0. Неизвестные поля в задачах отклоняются.
Некорректный запрос — `422`, некорректный ответ модели — `502/planner_invalid_response`,
недоступный/не настроенный провайдер — `503/planner_unavailable`.
Известные ошибки подключения имеют отдельные коды при HTTP `503`: `planner_quota_missing`,
`planner_credentials_invalid`, `planner_access_denied`, `planner_provider_limit`,
`planner_endpoint_not_found`. Сообщения стороннего сервиса напрямую клиенту не передаются.
Лимиты по умолчанию: 10 попыток на пользователя за календарный час UTC и 50 попыток
на всё приложение за календарные сутки UTC, далее `429`. Настройки — `AI_REQUESTS_PER_HOUR`
и `AI_GLOBAL_REQUESTS_PER_DAY`; ноль в последней полностью отключает генерацию.
Попытка резервируется атомарно в таблице `ai_usage_budgets` до обращения к прокси.
Счётчики общие для процессов с одной БД и сохраняются при рестарте. Ошибки провайдера,
невалидный ответ и timeout расходуют попытку: провайдер уже мог её тарифицировать.
Отклонение по персональному лимиту не расходует общий лимит. Недоступность таблицы/БД
даёт `503` до сетевого вызова. Для хранения счётчиков требуется миграция `0004_ai_limits`.

Генерация записывает только служебные счётчики; проект и задачи не создаются.
После проверки клиент передаёт черновик как необязательное поле
`personal_plan` в существующий `POST /api/projects`. Сервер валидирует его заново, добавляет
стандартные задачи и первый день, затем персональные пункты, исключая совпадения названий
без учёта регистра/повторных пробелов. Срок = дата переезда + `offset_days`.
Владелец, проект и все задачи сохраняются одной транзакцией. Без `personal_plan` поведение прежнее.
Изменение даты и описания на форме сбрасывает предпросмотр; описание не хранится в БД.

Диктовка — необязательный Web Speech API в браузере (`ru-RU`), без серверного аудиофайла.
При недоступном микрофоне/браузере доступен текстовый ввод. Аудио может обрабатываться
сервисом браузера; уведомление показано перед нажатием микрофона. Диктовка сама не запускает AI.

Настройка и ограничения: [FEATURES.md](FEATURES.md), раздел «ИИ-помощник».

- **Доступ:** вход по логину и паролю (раздел «Вход и приглашения»). Сессия — httpOnly-cookie `mm_session` (`SameSite=Lax`, на проде `Secure`), браузер отправляет её сам. Все пути `/api/projects…` требуют входа (`401` без него). Проект видят только его участники: чужой проект отвечает `404`, как несуществующий. Удалить проект и приглашать может только владелец (`403` для участника).
- **Коробка** адресуется номером `{n}` (целое ≥ 1), уникальным внутри проекта. Универсальный QR кодирует ссылку `{origin}/projects/{pid}/boxes/{n}`; компактный — постоянный `MM1:…`, который открывается через сканер сайта и resolver. Открытие карточки только читает, дублей не создаёт.
- **Ошибки** (формат шаблона, `backend/app/main.py`):

```json
{ "detail": "Коробка уже в статусе «packed»", "code": "conflict", "request_id": "…" }
```

Валидация (422) дополнительно содержит `"errors": [{"field": "name", "message": "…"}]`.

| Код | `code` | Когда |
|---|---|---|
| 400 | `bad_request` | нечитаемый запрос |
| 401 | `unauthorized` | не вошли, сессия истекла, неверный логин или пароль |
| 403 | `forbidden` | участник пытается удалить проект, пригласить людей, убрать другого участника, сменить режим QR; демо-проект нельзя удалить |
| 404 | `not_found` | нет проекта (или он чужой), коробки, вещи, задачи, приглашения |
| 409 | `conflict` | недопустимый переход статуса, пустая коробка дальше «собирается», занятый логин, попытка убрать владельца |
| 422 | `validation_failed` | неверные поля, нет `confirm=true` при удалении |
| 429 | `too_many_requests` | больше 10 неудачных входов за 5 минут с одного IP на один логин; больше 1200 запросов к `/api` в минуту или 30 регистраций в час с одного IP (заголовок `Retry-After`); исчерпан лимит ИИ |
| 502, 503 | `planner_*` | ИИ: ошибка или недоступность провайдера, ИИ не настроен |

- **Пагинация** (списки коробок, вещей, поиска, событий): `?page=1&page_size=50` (по умолчанию 1 и 50, максимум `page_size` = 200). Ответ:

```json
{ "items": [ … ], "total": 312, "page": 1, "page_size": 50 }
```

- **Сортировка детерминирована:** везде есть вторичный ключ `id`/`number`, одинаковый запрос всегда даёт одинаковый ответ.
- **Удаление с подтверждением:** `DELETE` требует `?confirm=true`, иначе 422. Диалог подтверждения показывает сайт. Успех — `204 No Content`.

## Статусы коробки

```
packing (собирается) → packed (собрана) → loaded (погружена) → delivered (доставлена) → unpacked (распакована)
```

Обычный переход (`POST …/transitions`): вперёд — только на следующий этап (`packing → packed → loaded → delivered → unpacked`), назад — на любой более ранний этап, без причины. Пропуск вперёд и тот же статус дают `409`. Пустую коробку без «заполнить позже» нельзя собрать. Старый `POST /boxes/{n}/status-corrections` с `{ "to": "packed", "reason": "…" }` оставлен для совместимости: только более ранний этап, причина необязательна (до 300 символов), пишется событие `box.status_corrected`. Сайт его больше не вызывает.

Этапы задач: `before`, `moving_day`, `after`.

## Схемы

```jsonc
// Project
{ "id": "uuid", "name": "Переезд на Лесную", "move_date": "2026-11-01",
  "address_from": null, "address_to": null, "qr_mode": "universal", "created_at": "…Z" }

// Task
{ "id": 1, "project_id": "uuid", "stage": "before", "title": "Заказать грузчиков",
  "due_date": "2026-10-25", "assignee": "Аня", "start_time": null, "end_time": null,
  "category": null, "category_color": null, "done": false, "done_at": null,
  "template_id": 3 }

// Box
{ "number": 12, "project_id": "uuid", "room": "Кухня", "status": "packed",
  "fill_later": false, "remind_at": null, "items_count": 6,
  "created_at": "…Z", "updated_at": "…Z" }

// Item
{ "id": 77, "box_number": 12, "name": "Чайник", "quantity": 1, "status": "packed", "lost": false, "first_day": false, "created_at": "…Z" }

// Event

```

## Служебные

### `GET /api/health`
Проверка работоспособности. `200 {"status": "ok", "db": "ok", "version": "…"}`; при недоступной БД `503`.

### `GET /api/config`
Настройки для сайта: `200 { "maps_api_key": "…" | null, "maps_provider": "maptiler" | "google" | null }`. Ключ подсказок адреса задаётся на сервере: `MAPTILER_API_KEY` (MapTiler Geocoding и Static Maps, важнее) или `GOOGLE_MAPS_API_KEY`; это браузерный ключ, ограниченный по адресу сайта. Без ключа подсказок адреса нет. Сайт обращается к сервису только после нажатия «Найти на карте» и предупреждает, что введённый адрес туда уходит. Записать ключ на ВМ: `scripts/vm-env.sh MAPTILER_API_KEY`.

### `GET /api/task-templates`
Шаблоны задач (хранятся локально, сидятся). `200 [{ "id": 3, "stage": "before", "title": "Заказать грузчиков", "default_offset_days": -14 }]`.

### `GET /api/tips`
Памятки. `200 [{ "id": 1, "topic": "fragile" | "carry_with_you" | "pack_last", "title": "…", "body": "…" }]`. Необязательный `?topic=`.

## Вход и приглашения

Хранятся только логин и хэш пароля (scrypt с солью); токен сессии и приглашения в базе лежит как SHA-256.

### `POST /api/auth/register`
`{ "username": "anna", "password": "…" }`. Логин 3–40 символов (латиница, цифры, `.`, `-`, `_`), без регистра; пароль 8–128. `201` User `{id, username}` и cookie сессии; `409`, если логин занят.

### `POST /api/auth/login`
То же тело. `200` User и cookie; `401` «Неверный логин или пароль» (одна формулировка, не выдаёт существующие логины); `429` при переборе.

### `POST /api/auth/demo`
Вход в демо-аккаунт без пароля, только при `SEED_DEMO=true` (иначе `404`). `200` User.

### `POST /api/auth/logout` · `GET /api/auth/me`
Выход (`204`, сессия удаляется) и текущий пользователь (`200` User или `401`).

### `POST /api/auth/password`
`{ "current_password": "…", "new_password": "…" }` (новый 8–128). `200` User: все прежние сессии закрываются, текущее устройство получает новую cookie. `401` при неверном текущем пароле, `403` для демо-аккаунта.

### `POST /api/projects/{pid}/invites`
Только владелец. `201 { "token", "path": "/invite/{token}", "expires_at" }`. Ссылка действует 7 дней, по ней может войти несколько человек.

### `DELETE /api/projects/{pid}/invites`
Только владелец. Отзывает все ссылки проекта: `200 { "revoked": 2 }`. Участники остаются.

### `GET /api/projects/{pid}/members`
Любой участник: `200 [ { "user_id", "username", "role" } ]`, владелец первым.

### `DELETE /api/projects/{pid}/members/{user_id}?confirm=true`
Владелец убирает участника, участник может выйти сам (`204`). `403` — участник пытается убрать другого, `409` — попытка убрать владельца, `404` — нет такого участника.

### `GET /api/invites/{token}`
Без входа: `200 { "project_name", "expires_at" }`, чтобы показать, куда зовут; `404`, если нет или истекло.

### `POST /api/invites/{token}/accept`
Нужен вход. Добавляет в проект участником (повторно — без дублей). `200` Project.

## Проекты

### `GET /api/projects`
Мои проекты: `200 [ { "id", "name", "move_date", "move_date_end", "role": "owner" | "member" } ]`.

### `POST /api/projects`
Создаёт проект со стандартными задачами и сроками `move_date + default_offset_days`, а также базовым списком первого дня. `plan_mode: "empty"` явно отключает оба набора. Поле `first_day: ["…"]` заменяет базовый список (до 20 строк по 200 символов); принятые `personal_plan.first_day` дополняют его без дублей. AI-задачи сохраняются в той же транзакции, после дедупликации со стандартными. Существующие проекты при обновлении не заполняются автоматически.

Запрос: `{ "name": "…", "move_date": "2026-11-01", "address_from": null, "address_to": null, "qr_mode": "universal", "plan_mode": "standard", "personal_plan": null, "first_day": null }`. `name` 1–120 символов, `move_date` обязательна: не раньше сегодняшнего дня по Москве и не дальше той же даты через 2 года (несуществующая дата — 30 февраля, 29 февраля не в високосный год — тоже `422` с понятным текстом), адреса необязательны (≤ 300). Переезд на несколько дней: `move_date` — первый день, `move_date_end` — последний (необязательно; не раньше `move_date` и не дольше 31 дня, иначе `422`); сроки задач считаются от `move_date`.
Ответ `201`: Project.

### `GET /api/projects/{pid}`
`200` Project; `404`, если нет.

### `PATCH /api/projects/{pid}`
Любые из `name`, `move_date`, `move_date_end` (`null` — переезд в один день), `address_from`, `address_to`, `qr_mode` (только владелец). Новая `move_date` проверяется так же, прежняя (уже прошедшая) не мешает сохранять другие поля. Смена `move_date` сдвигает на ту же разницу сроки невыполненных задач стандартного плана и `move_date_end`, если тот не прислан в том же запросе. `200` Project.

### `DELETE /api/projects/{pid}?confirm=true`
Только владелец. Удаляет проект и всё внутри (каскад). `204`; `403` для демо-проекта (он общий для жюри).

## Задачи (5.1)

### `GET /api/projects/{pid}/tasks`
Фильтры: `stage`, `done` (`true|false`). Сортировка: `stage` (before, moving_day, after), `due_date` (без срока — в конце), `id`. Без пагинации (десятки записей). `200 [Task]`.

### `POST /api/projects/{pid}/tasks`
`{ "stage": "before", "title": "…", "due_date": null, "start_time": "09:00", "end_time": "12:30", "category": "Грузчики", "category_color": "#f0a04b", "assignee": null }`. Всё, кроме `stage` и `title`, необязательно. `title` 1–200, `assignee` ≤ 80, `category` ≤ 40. Время — `ЧЧ:ММ` без часового пояса, конец позже начала (иначе `422`); в ответе `ЧЧ:ММ:СС`. `category_color` — `#RRGGBB`, без категории цвет не хранится. `201` Task. Событие `task.created`.

### `PATCH /api/projects/{pid}/tasks/{tid}`
Любые из `title`, `stage`, `due_date`, `start_time`, `end_time`, `category`, `category_color`, `assignee`, `done`; `null` очищает необязательное поле. Время проверяется по итоговым значениям (можно прислать только `end_time`). Сброс `category` сбрасывает и цвет. При `done: true` ставится `done_at`. `200` Task. Событие `task.completed` / `task.reopened`.

### `DELETE /api/projects/{pid}/tasks/{tid}?confirm=true`
`204`.

### `POST /api/projects/{pid}/tasks/apply-templates`
Добавляет шаблонные задачи, которых ещё нет (идемпотентно, по `template_id`). `200 { "added": 4 }`.

## Коробки (5.2)

### `GET /api/projects/{pid}/boxes`
Фильтры: `room` (точное совпадение), `status`, `location` (`old` — `packing|packed`, `truck` — `loaded`, `new` — `delivered|unpacked`), `fill_later` (`true|false`), `number` (точный номер), пагинация. Фильтры пересекаются и применяются до подсчёта `total` и пагинации. Сортировка: `number` по возрастанию. `200` страница Box.

### `POST /api/projects/{pid}/boxes`
`{ "room": "Кухня", "fill_later": false, "remind_at": null, "items_text": null }`.
- `room` 1–60 символов, обязательна.
- Номер выдаёт сервер: `max(выданных номеров) + 1` внутри проекта под блокировкой проекта; выданные номера берутся из коробок и журнала `box.created`, поэтому номер удалённой коробки не выдаётся снова (старая наклейка не откроет чужую коробку). `UNIQUE(project_id, number)` — страховка. Клиент номер не передаёт.
- `items_text` необязательно: строки = вещи (то же, что `bulk`).
- `fill_later: true` допускает пустую коробку; `remind_at` необязательна.
`201` Box. Событие `box.created`.

### `GET /api/projects/{pid}/boxes/{n}`
Карточка коробки (то, что открывает QR): Box плюс `items: [Item]`. `200`; `404`, если номера нет. Не создаёт ничего.

### `PATCH /api/projects/{pid}/boxes/{n}`
Любые из `room`, `fill_later`, `remind_at`. Номер и статус сюда не входят. `200` Box.

### `DELETE /api/projects/{pid}/boxes/{n}?confirm=true`
Удаляет коробку и её вещи. Номер удалённой коробки больше не выдаётся (ни из середины, ни последний). `204`. Событие `box.deleted`.

### `POST /api/projects/{pid}/boxes/{n}/transitions`
`{ "to": "loaded" }`. Проверка по таблице переходов. `200` Box. Ошибки: `409` (тот же статус или пустая коробка), `422` (неизвестный статус). Событие `box.status_changed` с `from`/`to`.
Дополнительно: пустую коробку (`fill_later = false`, вещей нет) нельзя перевести из `packing` ни в какой другой статус → `409` с понятным текстом.

### `POST /api/projects/{pid}/boxes/bulk-transitions`
Для чек-листа погрузки: `{ "numbers": [1,2,3], "to": "loaded" }`. Применяется атомарно: если хоть один переход недопустим, не меняется ничего, `409` с перечнем номеров. `200 { "updated": [Box] }`.

## Вещи (5.2, 5.4)

### `GET /api/projects/{pid}/boxes/{n}/items`
Пагинация. Сортировка: `id`. `200` страница Item.

### `POST /api/projects/{pid}/boxes/{n}/items`
`{ "name": "Чайник", "first_day": false, "status": "packed" }`: `name` 1–120 символов, остальное необязательно (вещь первого дня и начальный статус). `201` Item.

### `POST /api/projects/{pid}/boxes/{n}/items/bulk`
Быстрый ввод: `{ "text": "Чайник\nКружки (4 шт)\nТостер" }`. Каждая непустая строка = вещь, пробелы по краям срезаются, пустые строки игнорируются, максимум 200 строк за запрос. Дубли внутри коробки не схлопываются (две одинаковые вещи допустимы). `201 { "created": [Item] }`. Сбрасывает «ожидание заполнения» (`fill_later` остаётся флагом, но напоминание исчезает, как только в коробке есть вещь).

### `PATCH /api/projects/{pid}/items/{id}`
Любые из `name`, `quantity`, `status`, `damaged`, `first_day` (понадобится в первый день). У вещи две независимые отметки: потеряна/нашлась (`status`: `packed`, `unpacked`, `found`, `lost`; на сайте — кнопки «Не могу найти» / «Нашлась») и повреждена (`damaged: true|false`, миграция 0010; `status: damaged` принимается для совместимости). Неизвестный статус — `422`. Старый формат `lost: true|false` принимается как `status: lost|found`. `200` Item. События `item.lost`, `item.found`, `item.status_changed` с `from`/`to`, `item.damage_changed`.

### `POST /api/projects/{pid}/items/{id}/move`
Переложить вещь в другую коробку того же проекта: `{ "from_box_number": 1, "to_box_number": 2 }`. Атомарно: если вещь уже переложили из `from_box_number` в другую коробку — `409` «Вещь уже переложили…»; повтор в ту же коробку — `200` без изменений. `200` Item. Событие `item.moved` с `from_box`, `to_box`.

### `DELETE /api/projects/{pid}/items/{id}?confirm=true`
`204`.

### `GET /api/projects/{pid}/items/lost`
Список потерянных вещей проекта, с коробкой, комнатой и статусом. `200 [{ item, box_number, room, status }]`.

### `GET /api/projects/{pid}/items/first-day`
Вещи с пометкой «первый день» в том же формате, по номеру коробки. Для вкладки «Первый день» в «Плане».

### `GET /api/projects/{pid}/items/{id}/hints`
Подсказки: в каких **нераспакованных** коробках искать вещь. Берутся коробки со статусом не `unpacked`, кроме коробки самой вещи, если она уже записана в этой коробке (тогда она первая, `reason: "recorded"`).
Ранжирование (детерминированное, оценка по убыванию, потом номер):
1. `recorded` — вещь записана в этой коробке.
2. `similar_content` — в коробке лежат вещи со схожими словами в названии.
3. `same_room` — коробка предназначена для той же комнаты, что и коробка вещи.
`200 [{ "box_number": 7, "room": "Кухня", "status": "delivered", "reason": "same_room", "score": 0.6 }]`, максимум 10.

## Поиск (5.3)

### `GET /api/projects/{pid}/search?q=чайник`
Поиск вещей по названию среди всех коробок проекта. Регистр не важен, `ё = е`. Пагинация. `q` — минимум 1 символ (после обрезки пробелов).
Ранжирование: точное совпадение, затем начало слова, затем вхождение; внутри группы `box_number`, затем `item.id` (детерминировано).
Ответ — страница:

```json
{ "items": [
  { "item_id": 77, "name": "Чайник", "item_status": "packed", "lost": false,
    "box_number": 12, "room": "Кухня", "status": "packed" }
  ], "total": 1, "page": 1, "page_size": 50 }
```

Коробку по номеру ищут через `GET /boxes?number=12` или `GET /boxes/{n}`.

Данные этикетки; изображение QR строит сайт в браузере.

{ "number": 12, "room": "Кухня", "project_name": "Переезд на Лесную",

## Контроль и прогресс (5.4)

### `GET /api/projects/{pid}/progress`

```json
{
  "boxes_total": 40,
  "by_status": { "packing": 5, "packed": 10, "loaded": 8, "delivered": 7, "unpacked": 10 },
  "unpacked_percent": 25.0,
  "rooms": [
    { "room": "Кухня", "total": 12,
      "by_status": { "packing": 1, "packed": 2, "loaded": 3, "delivered": 2, "unpacked": 4 },
      "loaded": 9, "loaded_percent": 75.0,
      "unpacked": 4, "unpacked_percent": 33.3 }
  ],
  "coverage": 0.9
}
```

- `loaded` в комнате = коробки со статусом `loaded` и дальше (`loaded + delivered + unpacked`): уже погружены. Это данные для «чек-листа погрузки по комнатам».
- `unpacked_percent` = `unpacked / total` (по всем коробкам комнаты; вопрос 6 в `CASE.md`).
- `coverage` = коробки хотя бы с одной вещью / все коробки.
- Комнаты отсортированы по названию.

### `GET /api/projects/{pid}/reminders`
Коробки, о которых надо напомнить: `fill_later = true` и в коробке нет вещей, и (`remind_at` пуст или `remind_at ≤ сейчас`). `200 [{ "box": Box, "overdue": true }]`.

### Чек-лист первого дня (пункты-тексты)

Пункты хранятся отдельно от задач этапов. Проект со стандартным планом получает базовый список («Что подготовить»: зубные щётки, зарядки, чайник, постельное бельё), пустой план — пустой список; умный чек-лист дописывает пункты под особенности переезда. На сайте это вкладка «Первый день» на «Плане» («Что подготовить» — эти пункты, «В коробках» — вещи с `first_day = true` из `GET …/items/first-day`); `POST …/first-day/{id}/bind` кладёт пункт в коробку.

- `GET /api/projects/{pid}/first-day` → `200 [{ "id": 1, "title": "Зубные щётки", "done": false }]`, сортировка по `id`.
- `POST /api/projects/{pid}/first-day` `{ "title": "Чайник" }` → `201`.
- `PATCH /api/projects/{pid}/first-day/{id}` `{ "done": true, "title": "…" }` → `200`.
- `DELETE /api/projects/{pid}/first-day/{id}?confirm=true` → `204`.

## Умный ассистент (раздел 6 ТЗ)

Умный чек-лист работает **локально, на правилах**, без внешних вызовов. ИИ-функции (ниже) вызывают LLM-прокси Spirit только при `consent: true`; ответы только предлагают, данные меняются отдельным вызовом пользователя.

### `POST /api/projects/{pid}/assistant/checklist`
`{ "with_children": true, "with_pets": false, "other_city": true, "renting": true, "paperwork": false, "declutter": false, "settling": false }` → `200 { "suggested_tasks": [{ "stage": "before", "title": "Собрать документы и медкарту ребёнка", "reason": "with_children" }], "suggested_first_day": [] }`. Флаги: дети, питомцы, другой город, аренда (осмотр и акт), документы и смена адреса, разбор вещей, «обжиться».
`POST /api/projects/{pid}/assistant/checklist/apply` с тем же телом добавляет предложенное (идемпотентно, не дублирует заголовки). `200 { "added_tasks": 5, "added_first_day": 0 }`.

### `POST /api/projects/plan-questions` → `POST /api/projects/plan-preview`
Шаг 1: `{ "description": "Переезжаем с собакой и пианино", "move_date": "2026-12-01", "consent": true }` → `200 { "questions": [{ "id": "q1", "question": "Есть ли грузовой лифт?", "options": ["Да, в обоих", "Нет лифта"] }] }` (до 3 вопросов). Шаг 2: то же тело плюс `"answers": [{ "question": "…", "answer": "Нет лифта" }]` (до 5) → черновик `{ "tasks": [{ "title", "stage", "offset_days" }], "first_day": [] }`; сохраняется в `POST /api/projects` полем `personal_plan`. Модель — `AI_MODEL`.

### `POST /api/projects/{pid}/boxes/{n}/photo-inventory`
`{ "image": "data:image/jpeg;base64,…", "consent": true }` → `200 { "items": [{ "name": "Кружки (4 шт)", "first_day": true, "fragile": true }] }`. Только участник проекта, коробка должна существовать (`404` до вызова модели). Фото: JPEG/PNG/WebP, до 4 МБ, проверяется **до** списания попытки. В коробку ничего не пишется: сайт подставляет опись в форму `items/bulk`.

### `POST /api/projects/{pid}/room-plan`
`{ "image": "data:image/jpeg;base64,…", "room": "Кухня", "consent": true }` → `200 { "room": "Кухня", "boxes": [{ "label": "Посуда", "items": ["Тарелки", "Бокалы"], "tip": "Каждую тарелку в бумагу" }] }` (до 10 коробок). Коробки создаются только выбранные пользователем через `POST …/boxes`.

Фото-ручки используют `AI_VISION_MODEL` и `AI_VISION_API_KEY` (если заданы, иначе основные). Ошибки: `422` нет согласия или плохое фото, `429` лимит (общий с планом: `AI_REQUESTS_PER_HOUR` на пользователя, `AI_GLOBAL_REQUESTS_PER_DAY` на всех), `502` некорректный ответ модели, `503` ИИ не настроен или провайдер недоступен.

## Полный путь переезда: калькулятор и бюджет

### `POST /api/calculator` (нужна сессия)
`{ "rooms": 2, "people": 3, "distance_km": 15, "floor_from": 5, "elevator_from": false, "pets": true, "move_date": "2026-11-28", "city": "kzn" }` → `200 { "boxes": {"low","high"}, "volume_m3": {…}, "vehicle": "Грузовик 18–20 м³", "movers": 3, "hours": {…}, "prep_weeks": 3, "costs": [{ "category": "movers", "title": "Грузчики: 3 чел. × 4–6 ч", "cost": {"low": 8500, "high": 16000} }], "total": {…}, "date_advice": ["Выходной день: …"], "assumptions": "Ориентировочная оценка…" }`. Ничего не сохраняет; без входа `401`.

Поле `city` — slug из `GET /api/cities`; неизвестный город — `422`, без города — средние цены по 16 городам. Ответ дополнительно содержит `city` (название) и в `assumptions` — источник цен и дату проверки. Пределы: комнат 1–8, людей 1–10, 0–500 км, этаж 0–100 (без лифта не выше 15-го).

### `GET /api/cities`
`200 [{ "slug": "msk", "name": "Москва" }, …]` — 16 городов по алфавиту, цены грузчиков и Газели для калькулятора (Профи.ру, проверено 17.10.2026). Без входа.

### `GET /api/projects/{pid}/expenses`
`200 { "items": [{ "id", "category", "title", "planned", "actual" }], "planned": 39250, "actual": 22500, "variance": 1000 }` — `variance` считается по статьям с внесённым фактом (минус — экономия).

### `POST /api/projects/{pid}/expenses` · `PATCH …/expenses/{id}` · `DELETE …/expenses/{id}?confirm=true`
`{ "category": "movers", "title": "Грузчики", "planned": 12000 }` → `201`; `PATCH { "actual": 13500 }` вносит факт, `{ "actual": null }` сбрасывает. Категории: `movers | transport | materials | cleaning | services | rent | other`. Статья чужого проекта — `404`.

## Тест-сценарии, которые этот контракт должен выдержать

| Сценарий | Ожидание |
|---|---|
| Два параллельных `POST /boxes` | номера разные, без пропусков внутри проекта, без 500 |
| `transitions` `packing → unpacked` | `409` (нельзя распаковать недоставленную коробку) |
| `transitions` в тот же статус | `409` |
| `transitions` `delivered → unpacked` | `200` |
| `GET /boxes/12` дважды, затем `GET /boxes?number=12` | одна и та же коробка, `total` не меняется |
| `GET /search?q=чайник` дважды | идентичный ответ, идентичный порядок |
| `DELETE` без `confirm=true` | `422`, данные на месте |
| `bulk-transitions` с одним недопустимым номером | `409`, ни один статус не изменён |
| Проект на 300 коробок и 3000 вещей | `GET /boxes`, `/search`, `/progress` отвечают быстро (цель ≤ 300 мс на обычной машине) |
| Обновление страницы | состояние берётся из API по сохранённому `pid` |


### Единый сценарий первого дня

`GET /first-day` возвращает подготовительные пункты, включая принятые AI-рекомендации; `GET /items/first-day` — фактические вещи в коробках. Оба набора отображаются на вкладке «Первый день» и на «Прогрессе».

`POST /projects/{pid}/first-day/{item_id}/bind` принимает `{ "box_number": 1, "name": "Чайник" }` (имя необязательно). В одной транзакции находит одноимённую вещь выбранной коробки или создаёт её, устанавливает `first_day=true`, удаляет подготовительный пункт и пишет событие. Отсутствие коробки или чужой проект не меняет список; повтор после успешной привязки возвращает `404` без дубля вещи.

### Большие проекты

Основной экран коробок использует страницы по 36, поиск — по 50. Фильтр комнаты выполняется сервером, в том числе `GET /search?q=…&room=…`. Полный список комнат и счётчики берутся из агрегированного `/progress`. Чек-лист погрузки на «Прогрессе» раскрывается по комнатам и тоже имеет страницы; обычные кнопки не пропускают этапы. Проверены 300 коробок и 300 совпадений поиска, включая комнату после первых 200 записей и возврат из карточки на последнюю страницу.

Количество `quantity` — целое число от 1 до 9999 (по умолчанию 1); принимается при создании и изменении вещи, возвращается в Item и SearchHit. `null`, дроби и строки отклоняются с 422. Миграция 0011 добавляет старым позициям количество 1, сохраняя названия буквально (включая написанное пользователем «6 шт.»). Массовый ввод создаёт позиции с quantity=1; количество можно исправить в карточке. `items_count` считает позиции описи, а не сумму quantity. Перенос перемещает всю позицию с количеством, идентификатором и отметками; частичное разделение не выполняется. Этикетки включают количество, если оно больше 1.

`GET /api/projects/{pid}/boxes` принимает `sort=number|open_first|closed_first` (по умолчанию number). Открытыми считаются packing и unpacked. Порядок группируется по открытости, затем по номеру; применяется до offset/limit и совместим с фильтрами room/location/status/number. Недопустимый sort возвращает 422.


### Краткая опись коробок и выбор назначения переноса

`Box` содержит `contents_preview: [{name, quantity}]` — до пяти первых позиций, в порядке добавления. `items_count` по-прежнему считает все позиции, полная опись находится в `GET /boxes/{n}`. Список коробок получает превью одним ограниченным запросом для всей страницы, без отдельных запросов на каждую коробку. Изменения вещи и перенос отражаются в следующем чтении списка; схема базы не меняется.

`GET /boxes` также принимает `q` (до 120 символов: номер, часть комнаты или названия любой вещи) и `exclude_number` (исключить исходную коробку). Поиск названий/комнат нормализует регистр и ё/е; `%` и `_` считаются буквальными символами. Фильтрация применяется до подсчёта и пагинации. При поиске совпавшие вещи показываются первыми в `contents_preview`, даже если они были дальше первых пяти позиций. Доступ остаётся в пределах выбранного проекта.
