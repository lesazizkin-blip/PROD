> Что делает каждый, в каком порядке и когда сверяемся. Опирается на `CASE.md` (минимум), `API.md` (контракт), `ARCHITECTURE.md` (решения), `PLAYBOOK.md` (расписание хакатона), `RULES.md` (правила).
> Имена не расписаны: распределите роли A–E в начале дня 1 и впишите в таблицу ниже.

## Стек клиента

**React Native + Expo (TypeScript), Android APK.** Выбрано как самое простое: тот же язык, что в шаблоне; на Mac не нужны Android Studio, Java и Xcode (на машине их сейчас нет): запуск на телефоне через Expo Go; APK собирается в облаке EAS (`eas build -p android --profile preview`).
Библиотеки: `expo-router` (экраны и deep link), `react-native-paper` (Material 3: компонентная база и гайдлайны), `@react-native-async-storage/async-storage`, `expo-camera` (сканер QR), `react-native-qrcode-svg` (QR локально), `expo-print` и `expo-sharing` (PDF и печать).
Веб-фронтенд шаблона (`frontend/`) не развиваем. Для мобильного жюри: APK в репозитории (раздел `releases/` или GitLab Release), единая компонентная база `ui/`, обработка ошибок и валидация полей, каждый участник понимает код.

## Принципы

1. **Контракт первым.** Фронтенд работает по `API.md` на заглушках, не ждёт бэкенд. Любое изменение контракта — правка `API.md` в том же коммите и сообщение в чат.
2. **Одна вертикаль насквозь, потом ширина.** Сначала «проект → коробка → список» на проде, потом остальное.
3. **Каждый merge в `main` уходит на прод.** Ветки короткие (до половины дня), в `main` только при зелёном CI.
4. **Минимум до красоты.** Штраф −30% за невыполненный минимум дороже любой фичи. ML — только после закрытия минимума.
5. **Каждый коммитит под своим именем** (Положение, п. 4.9): у каждого свои зоны и свои коммиты в GitLab. Каждый должен уметь объяснить свой код на защите.
6. **Не пересекаемся по файлам.** Зоны ниже; общие файлы (`models.py`, `types.ts`, `API.md`) правим короткими коммитами и сразу пушим.

## Риски и что делаем

| Риск | Действие |
|---|---|
| Сервер не выдан | Свой VPS (`DEPLOY.md`, путь 4), крайний случай `make tunnel` и честно сказать жюри |
| Деплой ломается ночью | A проверяет `preflight` вечером и утром; откат на предыдущий образ |
| Приложение и бэкенд разошлись | Источник правды — Swagger и `mobile/src/api/types.ts`; чиним сразу, не копим |
| APK не собирается (EAS, очередь, аккаунт Expo) | Завести аккаунт Expo и собрать пробный APK **в день 1**; запасной путь — `npx expo prebuild` + Gradle на машине с Android Studio; в крайнем случае показывать на Expo Go и сказать жюри честно |
| Android блокирует HTTP | Сервер отдаёт API по HTTPS; для локальной отладки — тот же Wi-Fi и `usesCleartextTraffic` только в debug-сборке |
| iOS-сборка недоступна (нужен платный Apple Developer) | Делаем Android APK; IPA не обещаем, на защите проверяем и показываем на Android |
| Не успеваем минимум | Вырезаем всё, что не входит в минимум; ML и фото — первыми |
| Конфликты в `models.py` / `types.ts` | Короткие коммиты, сразу push, перед правкой `git pull --rebase` |
| Кто-то выбыл | Зоны D и E взаимозаменяемы; C берёт поиск и прогресс, A — этикетки; ML отменяется |
| Положение ограничивает готовый шаблон | Раскрыть использование шаблона в README и на защите; план Б — `KICKOFF.md` |

## Определение «готово» для задачи

1. Работает на проде (не только локально).
2. Есть тест на правило или сценарий; CI зелёный.
3. Контракт `API.md` и типы `types.ts` соответствуют коду.
4. Для приложения: есть состояния загрузки, ошибки и пустого экрана; неверный ввод валидируется, приложение не падает при ошибке сети; компоненты берутся из `ui/`.
5. Строка в таблице минимума `CASE.md` отмечена ✅.
