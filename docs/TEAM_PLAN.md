## Принципы

1. **Контракт первым.** Любое изменение API — правка `API.md` в том же коммите и сообщение в чат.
2. **Одна вертикаль насквозь, потом ширина.** Сначала «проект → коробка → список» на проде, потом остальное.
3. **Каждый merge в `main` уходит на прод.** Ветки короткие (до половины дня), в `main` только при зелёном CI.
4. **Минимум до красоты.** Штраф −30% за невыполненный минимум дороже любой фичи.
5. **Каждый коммитит под своим именем** (Положение, п. 4.9): у каждого свои зоны и свои коммиты в GitLab. Каждый должен уметь объяснить свой код на защите.
6. **Не пересекаемся по файлам.** Зоны ниже; общие файлы (`models.py`, `api/types.ts`, `API.md`) правим короткими коммитами и сразу пушим.

## Риски и что делаем

| Риск | Действие |
|---|---|
| Сервер не выдан | Свой VPS (`DEPLOY.md`, путь 4), крайний случай `make tunnel` и честно сказать жюри |
| Нет HTTPS: камера в браузере не работает | HTTPS через сервер организаторов, Caddy или туннель; запасной путь — ввод номера коробки вручную на странице сканера, обычная камера телефона открывает ссылку из QR без HTTPS |
| Деплой ломается ночью | A проверяет `preflight` вечером и утром; откат на предыдущий образ |
| Сайт и бэкенд разошлись | Источник правды — Swagger и `frontend/src/api/types.ts`; чиним сразу, не копим |
| QR напечатан при запуске на другом адресе | Сканер на сайте принимает ссылку с любым адресом сайта; этикетки перепечатываются кнопкой «Печать всех» |
| Не успеваем минимум | Вырезаем всё, что не входит в минимум; `room-plan` и фото — первыми |
| Конфликты в `models.py` / `types.ts` | Короткие коммиты, сразу push, перед правкой `git pull --rebase` |
| Кто-то выбыл | Зоны D и E взаимозаменяемы; C берёт поиск и прогресс, A — этикетки |
| Положение ограничивает готовый шаблон | Раскрыть использование шаблона в README и на защите; план Б — `KICKOFF.md` |

## Определение «готово» для задачи

1. Работает на проде (не только локально).
2. Есть тест на правило или сценарий; CI зелёный.
3. Контракт `API.md` и типы `frontend/src/api/types.ts` соответствуют коду.
4. Для сайта: есть состояния загрузки, ошибки и пустого экрана; форма проверяет ввод; сайт не падает при ошибке сети; удобен и на телефоне, и на ноутбуке.
5. Строка в таблице минимума `CASE.md` отмечена ✅ только после проверки на проде.
