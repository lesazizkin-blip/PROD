# Деплой: что выбрать и как проверить заранее

**Недеплой = −20% баллов** (получили 41–61% команд в прошлых хакатонах). Это нужно настроить **до** хакатона и проверить боем.
Сейчас сервера под этот проект нет: прежние серверы удалены, так что первое действие — выбрать вариант.

## Вариант A. VPS с Docker (рекомендуется: стек уже готов под него)
Подойдёт любой дешёвый сервер (1–2 ГБ ОЗУ, Ubuntu 22.04/24.04) у любого хостера; домен не обязателен — достаточно `http://<IP>`.
Покупка сервера — ваше решение и ваши деньги; я это не делаю.

1. Сгенерировать ключ для деплоя (на своём компьютере): `ssh-keygen -t ed25519 -f ~/.ssh/prod_deploy -C prod-deploy`
2. Зайти на сервер под root, скопировать и запустить скрипт:
   ```bash
   scp scripts/bootstrap-server.sh root@<IP>:/root/
   ssh root@<IP> "bash /root/bootstrap-server.sh '$(cat ~/.ssh/prod_deploy.pub)'"
   ```
   Скрипт ставит Docker, создаёт пользователя `deploy` с вашим публичным ключом и включает файрвол (22, 80, 443). Он не проверялся на реальном сервере — прогоните заранее.
3. В GitHub → Settings → Secrets and variables → Actions:
   - Variable: `DEPLOY_ENABLED` = `true`
   - Secrets: `DEPLOY_HOST` (IP), `DEPLOY_USER` = `deploy`, `DEPLOY_SSH_KEY` (содержимое **приватного** `~/.ssh/prod_deploy`), `POSTGRES_PASSWORD`, `SECRET_KEY` (длинная случайная строка), `ADMIN_PASSWORD`
4. Пуш в `main` → джоба `deploy` → `http://<IP>/` и `http://<IP>/api/docs`.
5. Проверка: `scripts/preflight.sh http://<IP>` — все пункты `OK`. Для публичного сервера задайте `ADMIN_PASSWORD`, отличный от `admin12345`, и передайте его скрипту: `ADMIN_PASSWORD=... scripts/preflight.sh http://<IP>`.

Нюансы:
- Демо-данные включены (`SEED_DEMO=true`): для жюри это плюс; пароли демо-аккаунтов публичны — не держите на этом сервере ничего ценного.
- HTTPS в шаблон не включён (для хакатона достаточно HTTP). Если нужен — поставьте Caddy перед nginx и укажите домен.
- Образы собираются в CI и передаются по SSH — сборка на сервере не нужна, 1 ГБ ОЗУ хватает.

## Вариант B. PaaS (Render / Railway / Fly.io)
Подключаете репозиторий, указываете `backend/Dockerfile` и `frontend/Dockerfile`, подключаете PostgreSQL платформы.
Бэкенду нужны переменные `DATABASE_URL` (формат `postgresql+psycopg://...`), `SECRET_KEY`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `SEED_DEMO`.
Фронтенд (nginx) проксирует `/api` на хост `backend` — на PaaS это имя придётся заменить на адрес сервиса в `frontend/nginx.conf`.
Бесплатные тарифы засыпают и могут «просыпаться» минуту — не лучший вариант для защиты.

## Вариант C. Ничего нет к 16 октября
Развернуть прямо на хакатоне в первые часы по варианту B — но тогда **первым делом** и не позже обеда первого дня.
Запасной план: показать запущенное локально через `docker compose up` по видео и README — но штраф −20% за недеплой при этом, скорее всего, будет.
