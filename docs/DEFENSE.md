# Шпаргалка к защите

## Структура выступления (5 минут)

1. **Проблема и пользователь** (30 с): кто, какую боль решает, что получит.
2. **Демо** (1,5 мин): живой запрос в Swagger/UI, показать вилку и логи этого запроса.
3. **Данные и модель** (1,5 мин): ключевая находка EDA → признак → прирост метрики относительно baseline.
4. **MLOps** (1 мин): `dvc repro`, MLflow с несколькими запусками, CI зелёный, деплой по пушу.
5. **Бизнес-ценность** (30 с): что даёт продукт, главная метрика, как проверить гипотезу.

## Ответы на типичные вопросы

**Почему такие метрики?** MAE понятна бизнесу («ошибаемся в среднем на X ₽»); RMSE сильнее штрафует крупные промахи; R² — доля объяснённой дисперсии; coverage интервала — честность вилки (для 10–90 квантилей ожидаем ≈ 80%).

**С чем сравниваем?** С baseline «всегда медиана train». Если модель не бьёт его, она бесполезна.

**Что критичнее, FP или FN?** (для классификации) Подготовь ответ под кейс: например, при скоринге пропуск плохого заёмщика (FN) дороже, чем отказ хорошему (FP) — порог смещаем в сторону recall.

**Как воспроизвести результат?** `git clone && make setup && make repro`. Параметры в `params.yaml`, seed зафиксирован, версии данных/моделей — в DVC.

**Как отследить странный ответ модели?** В логах `/predict` пишется `request_id`, вход, выход, версия модели; `x-request-id` возвращается клиенту в заголовке.

**Как API справится с нагрузкой?** `make load` — показать throughput и p95. Узкое место — инференс sklearn; ONNX даёт ускорение (см. `reports/onnx_benchmark.json`). Масштабирование — несколько реплик контейнера за балансировщиком; есть `/predict/batch`.

**Что с утечкой данных?** Разбиение до любых fit-операций; импутация и кодирование обучаются только внутри `Pipeline` на train.

## Мини-правки: готовые рецепты

| Просят | Делаем |
|---|---|
| Новый признак по графику из EDA | `features.py: add_features()` → добавить столбец (+ имя в `EXTRA_NUMERIC`) → `make repro` → показать новый запуск в MLflow |
| Поменять порог классификации | В `model_service.py` заменить `0.5` на новый порог, показать precision/recall до/после |
| Новый эксперимент | Изменить значение в `params.yaml` → `make train` → открыть `make mlflow`, сравнить запуски |
| Воспроизвести обучение с нуля | `rm -rf models && dvc repro` (метрики совпадут) |
| Показать логи с временем | 3–5 запросов в Swagger → `tail -n 10 logs/api.log` |
| Нагрузочный тест | `make load` |
| Оптимизация инференса | `make onnx` → `reports/onnx_benchmark.json` |
| Добавить тест | Скопировать любой тест из `tests/test_api.py`, поменять вход/ожидание, `make test` |
