# Шпаргалка: критерии и «мини-правки»

План на три дня, роли и структура презентации — в `docs/reference/PLAYBOOK.md`; разбор прошлых хакатонов — в `docs/reference/ANALYSIS.md`.

## Как оценивают (по материалам прошлых хакатонов PROD)

Блоки: **Backend**, **Frontend**, **Product**, общее впечатление и структура презентации. Критерии — по 0–2 балла.
**Штрафы:** решение не задеплоено — **−20%**; не выполнен минимум из кейса — **−30%**. Поэтому: сначала живая ссылка, потом фичи.

**Backend (база):** деплой + Swagger по URL и CI/CD · OpenAPI с примерами · схема данных + миграции · тесты (unit на ключевые сценарии, интеграционные, хотя бы один негативный, отчёт в CI) · диаграммы доменных процессов.
**Backend (продвинутые):** слои и качество кода · БД (индексы, N+1, транзакции) · эволюция логики (схема → код → API → тесты → миграции, логи, диагностика 500).
**Frontend (база):** деплой по CI/CD · запросы к бэкенду, данные синхронны с UI · UX (предсказуемые элементы, нет «мёртвых» кнопок, валидация ввода) · единый стиль · адаптивность.
**Product:** проблема и пользователь · user path и user stories · бизнес-ценность посчитана · понятный UX · главная метрика (North Star) и способ проверки гипотезы.

## «Мини-правки» на защите — готовые рецепты

Жюри просит внести небольшое изменение прямо при вас. Тренируйтесь заранее. Пути ниже — реальные файлы MoverMate.

| Просят | Делаем |
|---|---|
| Новый статус коробки / переход | `BoxStatus` в `backend/app/schemas.py` → строка в таблице `TRANSITIONS` (`backend/app/services/boxes.py`) → тест в `tests/test_box_rules.py` → метка в `STATUS_LABELS` (`frontend/src/ui/format.ts`) и цвет `.st-<статус>` в `styles.css` |
| Новое поле в сущности | `backend/app/models.py` → `make migration m="add field"` (новый файл в `alembic/versions/`) → схемы в `schemas.py` → сервис → тест → поле в `frontend/src/api/types.ts` и форме. Пример целиком: время и категория задач, коммит `be60d79` и миграция `0002` |
| Индекс / оптимизировать запрос | `Index(...)` в `__table_args__` модели (`models.py`, например `ix_boxes_project_room_status`) → миграция; запрос показать в `services/` (поиск и прогресс в `services/boxes.py`) |
| Логика из контроллера в сервис | роутеры (`backend/app/routers/`) только принимают запрос и отдают ответ; правила в `backend/app/services/` |
| Новый тест-кейс | скопировать похожий из `backend/tests/`, поменять вход и ожидание, `cd backend && .venv/bin/python -m pytest` |
| Показать логи после запроса | запрос в Swagger (`/api/docs`) → на ВМ `docker logs --tail 50 deploy-app-1` → найти строку по `request_id` из ответа |
| «Что делать при 500 после релиза?» | клиент получает `request_id` → ищем в логах traceback → воспроизводим тестом → правим → тесты → передеплой (`docs/DEPLOY_VM.md`) → `scripts/preflight.sh` |
| Новое правило валидации | pydantic `Field(...)` / валидатор в `schemas.py` + та же граница на форме (пример: конец задачи позже начала) |

## «Мини-правки» по фронтенду

| Просят | Делаем |
|---|---|
| Новое поле в форме задачи | `TaskModal` в `frontend/src/pages/PlanPage.tsx`: состояние + `<label>`; тип в `api/types.ts`; тест в `pages/TaskModal.test.tsx` |
| Новый фильтр в списке коробок | `frontend/src/pages/BoxesPage.tsx`: состояние → параметр в `api.boxes(...)` (`api/endpoints.ts`); бэкенд уже принимает `room`, `status`, `fill_later`, `number` |
| Новая кнопка действия | обработчик через `useAction` (`frontend/src/state/useAction.ts`): блокирует кнопку на время запроса и показывает ошибку |
| Новый статус и цвет | `BoxStatus` в `api/types.ts`, `STATUS_LABELS` в `ui/format.ts`, `.st-<статус>` в `styles.css` |
| Показать обработку ошибки | остановить сервер или отправить неверные данные: форма показывает ошибку, экран — «Повторить» (`ui/StateView.tsx`) |
| Мобильная версия | DevTools → ширина 375: вкладки снизу, формы на всю ширину |
| Ссылка из QR | `/projects/<id>/boxes/<n>` открывает карточку коробки на любом устройстве, проект запоминается |

## Вопросы, к которым стоит быть готовыми
Почему слои router → service → model · как добавить новый статус коробки · почему переход только на шаг вперёд или назад (таблица `TRANSITIONS`, остальное 409) · как не выдать два одинаковых номера коробки (блокировка проекта + `UNIQUE(project_id, number)`) · где возможен N+1 и зачем индексы · почему нет авторизации (ТЗ: минимум персональных данных, доступ по UUID проекта; UUID не угадать) · почему чужая коробка отдаёт 404 · что произойдёт при 500 и где смотреть логи · почему SQLite, а не PostgreSQL (одна ВМ, срок 3 дня; тесты гоняются и на PostgreSQL) · почему умный чек-лист без внешнего ИИ (ТЗ запрещает скрытые передачи данных) · почему сайт, а не приложение.
