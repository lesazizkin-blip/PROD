# MoverMate: переезд без хаоса

Кейс №1 хакатона PROD (Т-Банк, ЦУ, ВШЭ), команда 20. Сервис помогает организовать переезд: план задач, коробки с номерами и комнатами, вещи, статусы, QR-этикетки, поиск вещи и прогресс.

- **Живой сайт:** https://hack-led-20-vm1-12902f.vmaas-spirit.t-education.com (Swagger: `/api/docs`)
- **Демо для жюри:** «Войти» → логин `demo`, пароль `demo-pereezd` (на сервере его задаёт `DEMO_PASSWORD`). Гость без входа видит страницу «О нас»; разделы открываются после регистрации или входа. Демо-проект «Переезд на Лесную» общий для всех, кто входит в демо.
- **Вход:** логин и пароль, без почты и телефона. Проект видят только его участники: владелец и те, кого он пригласил ссылкой (грузчики, родные).

## Что умеет сервис
Проект переезда → план задач на три этапа (пустой по умолчанию, типовые задачи и свои особенности — в умном чек-листе, сроки ставит пользователь) → коробки (номер, комната, вещи списком) → статусы коробки в окне выбора (собирается, собрана, погружена, доставлена, распакована; любой в любом порядке) → статус каждой вещи (упакована, распакована, найдена, потеряна, повреждена) → поиск вещи → QR-этикетки с печатью и сканером на сайте → прогресс по комнатам → потерянные вещи с подсказками, напоминания, вещи первого дня с чек-листом распаковки, умный чек-лист на правилах (без внешнего ИИ), памятка. Гость видит страницу «О нас» и «Вопросы».

Полная проверка требований ТЗ: `docs/CASE.md` (38 пунктов, статус и тест на каждый). Что ещё не сделано, см. «Статус» ниже.

## Стек
| Часть | Где | Технологии |
|---|---|---|
| Сервер | `backend/app` (роутеры → сервисы → модели) | FastAPI, SQLAlchemy, Alembic, SQLite |
| Сайт | `frontend/src` (pages, components, state, api, ui) | React 19, Vite, TypeScript, react-router |
| Образ | `Dockerfile` в корне | сайт и сервер в одном образе (`STATIC_DIR`) |
| Деплой | `deploy/` | Docker Compose, Caddy с автоматическим HTTPS |

Отдельного мобильного приложения нет: сайт адаптивный, QR открывается любой камерой.

## Быстрый старт
Нужны Python 3 и Node.js.

```bash
scripts/run-site.sh                 # сайт и API на http://localhost:8000 (сам ставит окружение)
```

Для разработки:

```bash
cd backend && python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt -c constraints.txt
cd backend && .venv/bin/alembic upgrade head && .venv/bin/python -m app.seed   # миграции и демо-проект
cd backend && .venv/bin/uvicorn app.main:app --reload                          # API на :8000
cd frontend && npm install && npm run dev                                      # сайт на :5173, /api проксируется на :8000
```

`python -m app.seed --load` добавляет нагрузочный проект (300 коробок, 3000 вещей).

## Проверки
```bash
cd backend && .venv/bin/python -m pytest --cov=app    # сервер: 96 тестов (+2 пропущены: параллельность проверяется на PostgreSQL в CI, проверка аннотаций — только на Python 3.14), покрытие 98%
cd frontend && npm test && npm run lint && npm run build   # сайт: 74 теста
scripts/preflight.sh <адрес>                          # полный сценарий ТЗ на запущенном сайте
```
Тесты сервера запускать из папки `backend/` (миграционный тест читает `alembic.ini` по относительному пути).

## Деплой
Автоматически из пайплайна GitLab: после слияния MR в `master` пайплайн прогоняет линтеры и тесты, собирает образ в Spirit Registry, выкатывает его на ВМ организаторов (с копией базы) и проверяет живой сайт `preflight.sh` (`docs/GITLAB.md`). Ручной передеплой остаётся запасным путём: `docs/DEPLOY_VM.md`.
