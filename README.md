# MoverMate: переезд без хаоса

Кейс №1 хакатона PROD (Т-Банк, ЦУ, ВШЭ), команда 20. Сервис помогает организовать переезд: план задач, коробки с номерами и комнатами, вещи, статусы, QR-этикетки, поиск вещи и прогресс.

- **Живой сайт:** https://hack-led-20-vm1-12902f.vmaas-spirit.t-education.com (Swagger: `/api/docs`)
- **Демо для жюри:** «Войти» → логин `demo`, пароль `demo-pereezd` (на сервере его задаёт `DEMO_PASSWORD`). Гость без входа видит страницу «О нас»; разделы открываются после регистрации или входа. Демо-проект «Переезд на Лесную» общий для всех, кто входит в демо.
- **Вход:** логин и пароль, без почты и телефона. Проект видят только его участники: владелец и те, кого он пригласил ссылкой (грузчики, родные).

## Что умеет сервис
Проект переезда → план задач на три этапа (стандартный по умолчанию, сроки относительно даты переезда; пустой план — явный выбор) → коробки (номер, комната, вещи списком) → статусы коробки в окне выбора (собирается, собрана, погружена, доставлена, распакована; строго по порядку; ошибочную отметку можно вернуть назад с причиной) → статус каждой вещи (упакована, распакована, найдена, потеряна, повреждена) → поиск вещи → QR-этикетки с печатью и сканером на сайте → прогресс по комнатам → потерянные вещи с подсказками, напоминания, первый день («Что подготовить» и «В коробках»), умный чек-лист на правилах, памятка. ИИ через LLM-прокси Spirit по согласию: план с уточняющими вопросами, опись коробки по фото, раскладка комнаты по фото (вторая модель для фото). Калькулятор переезда и бюджет «план–факт» (после входа), страница «Путь переезда» — 7 этапов от решения до «обжились». Гость видит «О нас», «Путь переезда» и «Вопросы».

Полная проверка требований ТЗ: `docs/CASE.md` (38 пунктов, статус и тест на каждый). Что ещё не сделано, см. «Статус» ниже.

## Стек

| Сервер | `backend/app` (роутеры → сервисы → модели) | FastAPI, SQLAlchemy, Alembic, SQLite |

Отдельного мобильного приложения нет: сайт адаптивный, QR открывается любой камерой.

## Быстрый старт
Нужны Python 3 и Node.js.

```bash
scripts/run-site.sh                 # сайт и API на http://localhost:8000 (сам ставит окружение)
```

Для разработки:

```bash
cd backend && python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt -c constraints.txt
cd backend && .venv/bin/alembic upgrade head && .venv/bin/python -m app.seed   # миграции и демо-проект
cd backend && .venv/bin/uvicorn app.main:app --reload                          # API на :8000
cd frontend && npm install && npm run dev                                      # сайт на :5173, /api проксируется на :8000
```

`python -m app.seed --load` добавляет нагрузочный проект (300 коробок, 3000 вещей).

## Проверки

### Этикетки и компактные QR

На странице «QR-этикетки» владелец выбирает общий формат проекта: универсальный (ссылка, обычная камера телефона) или компактный (20 символов, встроенный сканер MoverMate). Переключение не ломает старые распечатки. Есть четыре шаблона, в том числе без QR, выбор коробок/экземпляров и A4 на 4/8/12 этикеток. Без принтера можно написать номер маркером; инструкция находится в карточке коробки.

Постоянные коды хранит миграция `0004_compact_qr`: коробки и номера сохраняются, удалённые коды остаются зарезервированными. Миграции применяются сами при старте контейнера (`alembic upgrade head` в `Dockerfile`), перед выкаткой пайплайн делает копию базы.

### Локальный OCR-прототип для оценки

Рукопись ещё не прошла проверку качества. По умолчанию OCR выключен; доступен ручной номер `#001`. Для локальной экспериментальной оценки установлен pinned Tesseract.js, все worker/WASM/модель загружаются с того же сайта. Подготовка:

```bash
cd frontend
npm ci
npm run prepare:ocr -- /absolute/path/eng.traineddata.gz
VITE_LOCAL_OCR_PROTOTYPE=true npm run dev
```

Модель: `https://tessdata.projectnaptha.com/4.0.0/eng.traineddata.gz`, SHA-256 `ed350f3752f81ee8f38769edc14d92d997dababe23b565c59879372cc46a2468` (проверяется командой подготовки). Команда подготовки использует уже полученный локальный файл, не скачивает его. Каталог `frontend/public/recognition/` генерируемый и исключён из Git. На отдельной сборке с OCR его нужно подготовить до build и передать `VITE_LOCAL_OCR_PROTOTYPE=true` при сборке; один флаг без assets недостаточен. Для стандартной сборки модель не нужна. Не переносить локальное значение флага в production до оценки качества рукописи.

Фото обрабатывается локально, результат требует подтверждения. Полный план и фактические ограничения — `docs/LABELS_RECOGNITION_PLAN.md`.

На подготовленном OCR-стенде кнопка «Камера номера» запускает непрерывное распознавание: наведите на надпись в рамке, дождитесь найденной коробки и подтвердите открытие. Приложение автоматически выделяет строку, обрабатывает кадры по очереди и ждёт совпадения номера на двух кадрах. Фото/ручной ввод остаются запасными вариантами. Это эксперимент, проверенный на одном предоставленном почерке через виртуальный поток; физическая камера и другие надписи требуют отдельной проверки.

### Персональный план

Персональный AI-план при создании переезда: описание текстом/диктовкой → редактируемый
предпросмотр → сохранение с проектом. Это необязательное дополнение к локальным шаблонам;
нужны серверные настройки провайдера. [Настройка и ограничения](docs/AI_PLANNER.md).

## Деплой
Автоматически из пайплайна GitLab: после слияния MR в `master` пайплайн прогоняет линтеры и тесты, собирает образ в Spirit Registry, выкатывает его на ВМ организаторов (с копией базы) и проверяет живой сайт `preflight.sh` (`docs/GITLAB.md`). Ручной передеплой остаётся запасным путём: `docs/DEPLOY_VM.md`.
