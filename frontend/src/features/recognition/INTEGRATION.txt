Результат
- Сериализация владения QR-камерой между эффектами/StrictMode/remount; остановка после незавершённого старта, подавление старых callbacks, повторный запуск и фон/pagehide.
- Ошибка stop блокирует новое владение до перезагрузки. Браузерный запрос доступа к камере нельзя отменить через html5-qrcode: уход ждёт завершения start, затем освобождает поток. Новый поток до этого не запускается.
- Адаптивная рамка, задняя камера, конкретные сообщения об отказе/отсутствии/занятости камеры.
- Старый QR открывается после чтения актуальной коробки. MM1: + 16 Base32 — изолированный adapter реального endpoint, НЕ включён до готовности backend. Выбранный проект не влияет на QR.
- Номер #001/001/1: проверяется вся строка, положительное safe integer, нет извлечения цифр из текста. Выбранный проект назван явно. Существование/доступ проверяется сервером.
- Фото через file capture=environment после остановки QR, локальный preview, выделение прямоугольника доступными sliders, уменьшение области до 1600 px. JPEG/PNG/WebP <=12 MiB; до 40MP после декодирования; createImageBitmap/Canvas необходимы. HEIC не поддержан.
- OCR: исходный текст, до трёх нормализованных уникальных кандидатов, проверка существования каждого в выбранном проекте, выбор и отдельное подтверждение с повторным GET карточки. Нет создания/изменения статусов. >3 кандидатов требует переснять. 404 кандидата исключает его; сеть/доступ не превращаются в пустой результат.
- Отмена OCR/запоздалых ответов при уходе, фоне и смене проекта. Object URL освобождается; фото не сохраняется в storage и не отправляется в API. Намерение открыть QR после 401 сохраняется в sessionStorage на 5 минут без фото; при заблокированном storage сохранение после перезагрузки не гарантируется.

Что интегратору сделать (патч подготовлен, не применён)
1. git apply --check frontend/src/features/recognition/integration.patch
2. Применить патч: App получает необязательные services под build-time flags, package.json — ровно tesseract.js@6.0.1 и tesseract.js-core@6.1.2. Запустить npm install и передать обновлённый package-lock.json. Общие API-типы/contract.ts этой веткой не менялись; при переносе resolver в api/endpoints сохранить валидацию и тесты qr.ts.
3. VITE_COMPACT_QR_ENABLED=true — ТОЛЬКО после реализации и проверки реального POST /api/boxes/resolve-code, ошибок 401/404/422, чужих/удалённых кодов. Сейчас flag отсутствует: ясное сообщение, никаких mock-ответов. Обычные QR работают.
4. Для локального OCR-прототипа нужны self-hosted JS worker, WASM core и eng.traineddata.gz. Причина зависимости: браузер не предоставляет стандартного локального OCR handwritten numbers; тяжёлая обработка должна идти в worker. Tesseract — только измеримый baseline, не доказанный движок рукописи. Статический import зависимости в рабочий scanner отсутствует; модуль грузится по запросу фото.
5. Модель, использованная в техническом замере: https://tessdata.projectnaptha.com/4.0.0/eng.traineddata.gz . SHA256 ed350f3752f81ee8f38769edc14d92d997dababe23b565c59879372cc46a2468 . Сначала интегратор получает и проверяет локальный файл. Затем из frontend:
   node src/features/recognition/vendor-assets.mjs /absolute/path/eng.traineddata.gz
   Скрипт копирует ТОЛЬКО локальные assets в public/recognition; сетевых запросов в нём нет. Проверен в отдельном /tmp/movermate-vendor-check. Модель: 10,923,060 bytes; весь пакет core (все варианты): 30,606,788 bytes; JS facade 63,220, worker 111,162 bytes. Это размеры файлов, не замер скачивания на телефоне. Интегратору сохранить лицензии, кеширование и CSP для локального worker/WASM; не заменять пути CDN defaults.
6. VITE_LOCAL_OCR_PROTOTYPE=true — только для экспериментальной оценки, до качественной приёмки не объявлять рукопись готовой. Инициализация worker — на каждый вызов; кеш модели в IndexedDB отключён, завершение/таймаут 45с. Возможность тёплого worker стоит решать после оценки качества и памяти. Ограничение Tesseract.js: до завершения createWorker внешний handle недоступен; отменённый startup завершается после готовности, а зависшая/ошибочная инициализация может потребовать перезагрузку страницы для окончательного освобождения worker. После ошибки модели/таймаута startup повторные попытки этого prototype заблокированы до reload; глобальный throw библиотеки перехвачен errorHandler.
7. Путь «Нет принтера» после создания коробки принадлежит интегратору: инструкция написать #NNN и переход /scan с выбранным проектом. App/BoxPage/общий CSS этой реализацией не изменялись.
8. После общего соединения выполнить backend/frontend проверки и iOS/Android приёмку. Не включать compact/OCR flags только потому, что frontend-тесты зелёные.
